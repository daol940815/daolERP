- 상황: 2026-11-14부터 Vercel이 배포를 일시 중지(사유 "Fluid Active CPU — Hobby fair use 초과"). 안내상 2026-12-14까지.
  Hobby 한도는 Active CPU 월 4시간이며, 미들웨어 실행도 같은 한도에 포함된다.
- 주의 1: Hobby는 **비상업 개인 용도 전용**이다. 회사 ERP는 약관상 Hobby 대상이 아니다.
- 주의 2: 커뮤니티 사례상 30일이 지나도 자동으로 풀리지 않는 경우가 많다(수동 검토 요청 또는 Pro 전환).

### 원인 진단 (코드 기준 추정 — Vercel 사용량 화면의 함수별 Active CPU로 확인 필요)

1. **알림 폴링** `/api/notifications` — 열린 탭마다 20초 간격, 숨은 탭도 계속. 1회 호출 = 미들웨어(로그인 확인 + 권한 조회)
   + 라우트(로그인 확인 + 직원 조회 + 약 20개 조회, 4~5단계 순차). 직원 10명 × 탭 2개 × 9시간이면 하루 약 3만 회.
2. **사이드바 링크 미리 불러오기(prefetch)** — 배포 환경의 `next/link`는 화면에 보이는 메뉴 링크를 미리 요청한다. 링크마다
   미들웨어 + 레이아웃(AreaShell: 로그인 확인 · 직원 조회 · 화면 설정 조회) 서버 렌더가 돈다. 메뉴 수십 개 × 페이지 열 때마다.
3. 그 외: 대량 집계 API(카드 매출 동기화 300초, 대출 · 카드 60초 등)는 쓸 때만 돈다. 크론은 하루 1회라 무시할 수준.

### 실측 (2026-11-16 사용자 캡처 — Team Usage › Fluid Active CPU, 최근 30일)

- 일별: 11-02 이전 평일 2~6분 → 11-03부터 15~25분 → 11-10 이후 30~38분. 주말은 거의 0(화면을 켜 둔 시간에 비례).
- 종류별(Type): function 2시간 32분(64.1%) · middleware 1시간 25분(35.9%). 두 값이 같은 비율로 함께 증가 → 요청 횟수 증가가 원인.

- Pro 환산(미국 리전 단가 기준 추정): 지난 30일 약 1.5~2.5달러, 최근 1주 속도면 월 3~5달러 → 20달러 크레딧 안. Pro 실부담 = 월 20달러(관리자 1명).

### 검토했던 선택지

- A. Vercel Pro(월 20달러/인) — 상업 사용 정상, 즉시 재개, 코드 변경 없음.
- B. Oracle Cloud 상시 무료 VM(서울 리전) + `next start` — 무료 · 상업 가능 · 잠들지 않음. 서버 관리(재시작 · 보안 업데이트 · HTTPS) 필요,
  크론은 서버 cron으로.
- C. Cloudflare Workers(OpenNext) — 무료 플랜은 요청당 CPU 10ms라 이 앱에 부족, 유료 월 5달러면 충분. 이식 작업 필요.
- D. Render · Koyeb 등 무료 — 15분 무사용 시 잠들고 첫 접속 수십 초, 서울 리전 없음. ERP 용도로 비권장.
