# 상담일지·영업일지 트랙 인수인계 (2026-08-12 분리)

주문시스템 트랙(500번대)에서 상담일지 1차를 구현한 뒤, 상담일지·영업일지
고도화를 이 트랙(별도 세션)으로 분리했다. **마이그레이션 번호는 700번대 사용**
(500=주문, 600=매입처 허브, 400=회계, 300=개인화면, 200=근태, 100=허브).

## 중요 — 용어 정정 (사용자, 2026-08-12 / 정의 구체화 2026-08-11 이 트랙)

**영업일지 / 상담일지 / 업무일지는 서로 다른 개념이다.**

- **상담일지**: 고객처의 주문 관련 상담을 기록 → 주문 확정 시 주문서로 전환하는
  문서. 1차 구현 완료 (아래 참조).
- **영업일지**: 영업자가 **영업계획 또는 영업내용**(고객관리, 방문상담 등)을
  직접 기재하는 항목. 기존 `/me/journal` 화면(contact_activities, 인물 기준
  활동 기록, 105·300번대 트랙)이 이에 해당.
- **업무일지**: 해당 **계정이 ERP에서 진행한 업무 내용을 모두 기재**하는 항목
  (상담일지 작성, 주문서 작성 등등). 즉 계정 단위 ERP 활동 이력. 아직 미구현.
  사용자 목표: "00월 00일 A지점 A담당자와 상담" 형태로 상담일지 작성 내역이
  업무일지에 기재되는 연동. 세부 형태는 이 트랙에서 사용자와 확정할 것.

주문시스템 세션이 "업무일지 = 영업일지"로 가정하고 상담 저장 시
contact_activities에 '상담' 활동을 자동 기재하도록 구현했다 — 이 연동은
**잠정 구현**이며, 업무일지 개념이 확정되면 이 트랙에서 조정한다.

## 상담일지 1차 구현 상태 (주문시스템 트랙에서 완료, main 반영)

- 마이그레이션 506: `erp_consultations`(상담 본문) + `erp_consultation_items`
  (품목, 주문 품목과 같은 필드) + `erp_orders.consultation_id`(전환 연결) +
  contact_activities 활동 유형 '상담' 추가.
- 화면: `/orders/consultations` 목록(상태·구분 칩, 본인 기본/manager+ 전체 토글) ·
  작성/수정 폼(실물 '주문상담' 시트 컬럼 순서). 공용 부품은
  `app/(orders)/orders/form-shared.tsx` (주문 입력과 가격 규칙 공유).
- 전환: `/orders/new?consult=<id>` 프리필 → 저장 시 연결 + 상담 상태 '주문전환'
  (수정 잠금, 추가 전환으로 분할 주문 가능).
- 결제정보: AES-256-GCM 암호화(`lib/payment-crypto.ts`), 마스킹+열람.
  **PAYMENT_ENC_KEY 환경변수 필요, 변경 금지** (기존 암호문 복호화 불가).
- 실물 근거: 사용자 제공 주문상담 시트(3,588행) 분석 — 시안
  docs/mockups/상담일지_시안.html, 확정 사항은 docs/order-system-track.md
  "상담일지 기능" 절 참조.

## 업무일지 확정 사항 (사용자 결정, 2026-08-14)

1. **기록 범위 (1차)**: 상담일지 작성·수정·주문전환, 주문서 작성·수정.
   이후 발주·배송 등으로 단계 확장.
2. **열람 권한**: 본인은 자기 업무일지, manager/admin은 팀원 것도 열람.
3. **화면 위치**: 직원 워크스페이스 사이드바에 "내 업무일지" 추가
   (기존 "내 영업일지"와 나란히).
4. **잠정 구현 이관**: 상담 저장 시 contact_activities(영업일지) '상담' 활동
   자동 기재는 폐지하고 업무일지로 이관. 기존에 쌓인 '상담' 활동 데이터도
   업무일지로 이관 처리.

진행 순서: 시안(HTML) → 사용자 확인 → 마이그레이션(700번대) + 구현.
1차 시안: docs/mockups/업무일지_시안.html (자동 기록 목록·날짜 그룹·드릴다운).

### 업무일지 시스템 목표 (사용자, 2026-08-14)

1. 직원들이 어떤 업무를 하는지 기재하게 하여 **관리자가 직원 업무현황을 쉽게
   확인**하는 것. (현재는 수기 업무일지 — 직원도 불편하고 관리자도 즉시 확인 불가)
2. ERP 밖 업무의 직접 기재 필요 여부 검토 요청 → 검토 결과·결정 아래 기록.
3. 관리자가 직원별로 들어가 보지 않아도 되는 **집계 화면** 필요 여부 검토 요청
   → 검토 결과·결정 아래 기록.

### 목표 2·3 검토 결과 확정 (사용자 승인, 2026-08-14)

- **직접 기재 기능 추가**: 업무일지 화면 상단 한 줄 입력(내용 + 구분:
  회의/출고·포장/재고/기타). 자동 기록 줄은 수정 불가, 직접 기재 줄만 본인
  수정·삭제 가능. 수기 업무일지 대체가 목표이므로 필수 판단.
- **영업일지 작성도 자동 기재 대상에 추가**: 영업일지 작성 행위 자체를
  업무일지에 자동 기록 (방문상담 등을 이중 기재하지 않게).
- **관리자 집계 화면 추가**: "팀 업무 현황" — 기간(오늘/이번 주/월)별
  직원 × 유형 건수 표 + 마지막 활동 시각, 행 클릭 시 해당 직원 업무일지로
  드릴다운. **직원(sales)은 접근 불가, manager/admin만.**
- 셋 다 신규 기능이므로 **일단 구현 후 사용하면서 피드백**으로 다듬기로 함.

## 업무일지 1차 구현 (2026-08-14, 마이그레이션 700 — 사용자 실행 대기)

- **마이그레이션 `700_work_logs.sql`**: `erp_work_logs` 신설
  (employee_id, work_date(KST), logged_at, source auto|manual, action,
  category, content, ref_type/ref_id 드릴다운). 같은 파일에서 **잠정 구현 이관** —
  contact_activities의 자동 기재분(activity_type='상담' AND content가
  '…와 상담 (구분)' 형식)을 업무일지로 INSERT 후 원본 DELETE. 파일 안에
  드라이런·검증 쿼리 주석 포함. 재실행해도 중복되지 않음(NOT EXISTS 가드).
  영업일지의 '상담' 활동 유형 자체는 유지(직접 기재용).
- **자동 기재 연결** (`lib/work-log.ts`의 `recordWorkLog` — 실패해도 본 저장 유지):
  - 상담 생성 POST → '상담작성' / 상담 수정 PATCH → '상담수정'
  - 주문 생성 POST → '주문작성' (consultation_id 있으면 '주문전환')
  - 주문 수정 PATCH → '주문수정'
  - 영업일지 작성 POST(`/api/me/journal`) → '영업일지'
  - 상담 POST 응답 필드가 `journal_logged` → `work_logged`로 바뀜.
- **API**: `/api/me/worklog` GET(월·유형 필터, manager+는 ?employee=로 팀원 열람) ·
  POST(직접 기재) · PATCH/DELETE(본인 직접 기재분만 — 자동 기재 줄은 잠금).
  `/api/team/worklog` GET(period=today|week|month, sales 403).
- **화면**: `/me/worklog`(KPI 4장 + 월 셀렉트 + 유형 칩 + 한 줄 직접 기재 폼 +
  날짜 그룹 목록, 각 줄 원본 드릴다운) · `/me/team-worklog`(관리자 전용,
  직원 × 유형 집계 표, 활동 0건 직원도 표시, 이름 클릭 시 그 직원 업무일지로).
- **사이드바**: "내 업무" 그룹에 업무일지 추가, 팀 업무 현황은 role !== 'sales'만.
- 직접 기재 구분 기본값: 회의 / 출고·포장 / 재고 / 고객응대 / 기타
  (`lib/work-log.ts` WORK_LOG_CATEGORIES — 사용해보고 조정).

## 상담일지 품목 옵션(부자재) 추가 (사용자 확정 2026-08-18, 마이그레이션 701)

  `erp_consultation_items.parent_line_no` 추가 (504의 주문 품목과 동일 구조).

## 상담일지 개선 피드백 (사용자, 2026-08-18 — 진행 중)

   기재되게 할 예정 — 전환 매핑 바꿀 때 참고.
2. 상담 품목 합계에 **마진율 표시** 추가.
3. **부서(지점) 정제**: branchLabel이 법인 접두("(주)" 등) 때문에 업체명을 못
   떼는 버그 — 함수 수정(주문 폼 공용) + **기존 데이터 보정은 드라이런으로
   규모 먼저 확인** (사용자 지시). 업로드 주문(source='erp_upload')은 원본
   보존 원칙상 보정 제외, direct 주문·상담일지만 대상.
4. **품목 배송비 열 삭제 → 배송비를 옵션 행으로** (배송비(카톤단위)/배송비(카톤외)

   **시안 확인 후 확정** (사용자: 시안 봐야 판단 가능).
5. 품목에 **카톤단위 열 표시**.
6. **품번 열 폭 확대** (상품명과 비슷하게).
- 폼 하단 "영업일지 자동 기재" 안내 문구 → 업무일지로 정정 예정.

   기재** (배송비를 판매가에 녹이는 경우가 대부분 — 사용자 확정).
   주문 전환 시 배송비 품목은 일반 품목 행으로 그대로 넘어간다 (판매 0이라
   매출 오염 없음, 매입은 비용으로 정상 집계). 702의 칩 방식 의사 행은
   과거 저장분 호환용으로만 유지 (전환 시 기존 접기 로직 적용).
6. 목록 체크박스 + 선택 복사 — **상담 복제 확정 (2026-08-19)**: 선택한 품목
   줄로 새 상담 작성 프리필 (고객이 이전 주문 품목을 다시 찾는 경우).
   같은 상담의 줄만 함께 복제 가능. 결제정보(암호문)는 복사하지 않음.
7. 목록을 품목 행 단위로 전환 (상품 3개 = 3줄, 부자재·배송비 행 제외) —
   **2안 확정 (2026-08-19)**: 품목별로 표시하되 하나의 상담일지로 인식,
   주문서 전환은 지금처럼 상담 단위. (1안 — 여러 상담 합쳐 주문 1건 — 은
   상담:주문 1:N 구조·결제정보 충돌 문제로 보류, 요구 반복 시 제한된
   형태로 재검토.)

### 신규 매출처 인라인 등록 (사용자 확정 2026-08-26 — 구현 완료, 마이그레이션 불필요)
