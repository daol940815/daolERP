# 상담일지·영업일지 트랙 인수인계 (2026-08-12 분리)

주문시스템 트랙(500번대)에서 상담일지 1차를 구현한 뒤, 상담일지·영업일지
고도화를 이 트랙(별도 세션)으로 분리했다. **마이그레이션 번호는 700번대 사용**
(500=주문, 600=매입처 허브, 400=회계, 300=개인화면, 200=근태, 100=허브).

## 중요 — 용어 정정 (사용자, 2026-08-12 / 정의 구체화 2026-08-11 이 트랙)

**영업일지 / 상담일지 / 업무일지는 서로 다른 개념이다.**

- **상담일지**: 고객처의 주문 관련 상담을 기록 → 주문 확정 시 주문서로 전환하는
  문서. 1차 구현 완료 (아래 참조).
- **영업일지**: 영업자가 **영업계획 또는 영업내용**(고객관리, 방문상담 등)을
  직접 기재하는 항목. 기존 `/me/journal` 화면(contact_activities, 인물 기준
  활동 기록, 105·300번대 트랙)이 이에 해당.
- **업무일지**: 해당 **계정이 ERP에서 진행한 업무 내용을 모두 기재**하는 항목
  (상담일지 작성, 주문서 작성 등등). 즉 계정 단위 ERP 활동 이력. 아직 미구현.
  사용자 목표: "00월 00일 A지점 A담당자와 상담" 형태로 상담일지 작성 내역이
  업무일지에 기재되는 연동. 세부 형태는 이 트랙에서 사용자와 확정할 것.

주문시스템 세션이 "업무일지 = 영업일지"로 가정하고 상담 저장 시
contact_activities에 '상담' 활동을 자동 기재하도록 구현했다 — 이 연동은
**잠정 구현**이며, 업무일지 개념이 확정되면 이 트랙에서 조정한다.

## 상담일지 1차 구현 상태 (주문시스템 트랙에서 완료, main 반영)

- 마이그레이션 506: `erp_consultations`(상담 본문) + `erp_consultation_items`
  (품목, 주문 품목과 같은 필드) + `erp_orders.consultation_id`(전환 연결) +
  contact_activities 활동 유형 '상담' 추가.
- 화면: `/orders/consultations` 목록(상태·구분 칩, 본인 기본/manager+ 전체 토글) ·
  작성/수정 폼(실물 '주문상담' 시트 컬럼 순서). 공용 부품은
  `app/(orders)/orders/form-shared.tsx` (주문 입력과 가격 규칙 공유).
- 전환: `/orders/new?consult=<id>` 프리필 → 저장 시 연결 + 상담 상태 '주문전환'
  (수정 잠금, 추가 전환으로 분할 주문 가능).
- 결제정보: AES-256-GCM 암호화(`lib/payment-crypto.ts`), 마스킹+열람.
  **PAYMENT_ENC_KEY 환경변수 필요, 변경 금지** (기존 암호문 복호화 불가).
- 실물 근거: 사용자 제공 주문상담 시트(3,588행) 분석 — 시안
  docs/mockups/상담일지_시안.html, 확정 사항은 docs/order-system-track.md
  "상담일지 기능" 절 참조.

## 업무일지 확정 사항 (사용자 결정, 2026-08-14)

1. **기록 범위 (1차)**: 상담일지 작성·수정·주문전환, 주문서 작성·수정.
   이후 발주·배송 등으로 단계 확장.
2. **열람 권한**: 본인은 자기 업무일지, manager/admin은 팀원 것도 열람.
3. **화면 위치**: 직원 워크스페이스 사이드바에 "내 업무일지" 추가
   (기존 "내 영업일지"와 나란히).
4. **잠정 구현 이관**: 상담 저장 시 contact_activities(영업일지) '상담' 활동
   자동 기재는 폐지하고 업무일지로 이관. 기존에 쌓인 '상담' 활동 데이터도
   업무일지로 이관 처리.

진행 순서: 시안(HTML) → 사용자 확인 → 마이그레이션(700번대) + 구현.
