# 근태 관리 설계 (인사·근태 트랙 1단계 — 마이그레이션 200)

## 원칙

- 직원 마스터는 `employees` 단일 테이블. 근태용 새 직원 테이블을 만들지 않고
  `attendance_target`(근태 대상 여부) 컬럼만 추가했다.
- 상태(지각·결근·휴가)는 저장하지 않는다. 정책(`attendance_policy`) ·
  출퇴근 기록(`attendance_records`) · 승인된 휴가(`attendance_leaves`)를 조합해
  화면·집계 시점에 자동 판정한다 (`lib/attendance.ts`의 `judgeDay`).
- 관리자 보정은 기록을 덮어쓰되 `edited_by / edited_at / edit_note`로 감사 이력을 남긴다.
  보정 사유는 필수.
- 모든 테이블 접근은 서버 라우트(service role) 경유. RLS enable + 정책 없음
  (기존 100번대 테이블과 동일 패턴).

## 출퇴근 체크는 등급 구분 없음

sales·manager·admin 모두 동일하게 출퇴근 체크·휴가 신청을 사용한다. 직원 등록 기능
이전부터 쓰던 관리자 계정처럼 `employees`와 연결되지 않은 로그인 계정은
`lib/attendance-employee.server.ts`의 `getAttendanceEmployee`가 최초 사용 시
자동으로 직원 행을 찾아 연결하거나 새로 만든다(이메일 앞부분을 임시 이름으로 사용 —
직원·계정 관리에서 수정). 별도의 연결 절차·화면은 두지 않는다.

체크를 사용하면 `attendance_target`이 자동으로 true가 되어 근태 현황 집계에도 잡힌다.

## 근태 대상 (CLAUDE.md의 미결 질문에 대한 처리)

로그인 계정 없는 직원(거래처 엑셀 적재로 등록된 상담자 21명)의 근태 대상 여부는
코드에서 확정하지 않았다. 마이그레이션 기본값으로 **계정 보유자만 대상**
(`auth_user_id IS NULL → attendance_target = false`)으로 두고, 근태 현황 화면의
"근태 대상 관리"에서 개별로 켜고 끌 수 있다 — 확정은 사용자가 한다.

## 데이터 구조 (200_attendance_base.sql)

| 테이블 | 내용 |
|---|---|
| `employees.attendance_target` | 근태 대상 여부 (기본: 계정 보유자만 true) |
| `attendance_records` | 출퇴근 기록. 직원·날짜(UNIQUE)당 1행. `source` self/admin, 보정 감사 컬럼 |
| `attendance_leaves` | 휴가 신청·승인. requested → approved/rejected/canceled. 반차는 하루짜리만 |
| `attendance_policy` | 단일 행 정책: 출근·퇴근 기준 시각, 지각 유예(분) |
| `attendance_holidays` (201) | 공휴일·휴무일. `source` public(법정, 연도 단위 교체 대상)/company(회사 휴무, 보존) |

### 공휴일 (201, 2026-09-29 실행 완료 · 2026-10-12 main 병합·배포)

- 공휴일은 주말과 동일하게 근무일에서 제외된다 — 결근·지각 판정 대상이 아니고,
  휴가 일수 계산에서도 빠진다. 공휴일이 주말과 겹치면 휴일명을 우선 표시한다.
- 관리 화면: 근태 현황(`/hr/admin`) > **공휴일 관리** (연도 선택·불러오기·직접 등록·삭제).
- **연도별 공급 — 공공데이터포털 특일정보 API**: "OOOO년 공휴일 불러오기" 버튼이
  한국천문연구원 특일 정보(`SpcdeInfoService/getRestDeInfo`)를 12개월치 호출해
  그 해 법정공휴일로 교체한다. 음력 기반(설날·부처님오신날·추석)·대체공휴일·임시공휴일이
  모두 공식 값으로 들어오므로, 201의 2026년 초기값도 이 버튼으로 덮어쓰는 것을 권장한다.
  - 환경변수 `DATA_GO_KR_SERVICE_KEY` (Vercel 등록 완료, 2026-09-29). 포털의 Decoding/
    Encoding 키 어느 쪽이든 동작한다(이중 인코딩 방지 처리).
  - 교체 대상은 `source='public'` 행뿐 — 직접 등록한 회사 휴무는 보존된다.
  - API가 0건을 반환하면 교체하지 않는다(일시 오류로 기존 공휴일이 지워지는 것 방지).
- **미등록 경고**: 해당 연도 공휴일이 0건이면 근태 현황에 경고 배너(+등록 버튼),
  내 근태에 안내 문구가 뜬다. 등록하지 않으면 그 해 공휴일이 조용히 결근으로 판정되므로
  이 경고가 유일한 방어선이다. 운영 루틴은 **연 1회 불러오기 버튼**.
- 권한: 조회·편집 모두 인사·총무(`isHrAdmin`). `API_OWNERS`에
  `/api/attendance/holidays` → `hr`로 등록(더 긴 접두 우선). 직원 화면은 이 API를
  호출하지 않고 `/api/attendance/records`가 내려주는 공휴일 맵만 사용한다.

날짜는 KST 기준(`work_date`). timestamptz는 UTC로 저장하고 화면·판정 시 +9h 변환
(한국은 DST 없음).

## 판정 규칙 (lib/attendance.ts)

- 주말(토·일)과 공휴일(`attendance_holidays`)은 근무일에서 제외 — 결근·지각 판정 대상이
  아니고, 휴가 일수 계산에서도 빠진다.
- 종일 휴가(연차·병가·공가·기타) 승인 → 휴가.
- 출근 체크 있음 → 출근. 기준 시각+유예 초과 체크인 → 지각 (오전 반차 날은 지각 판정 제외).
- 지난 날짜에 출근만 있고 퇴근 없음 → 퇴근 미기록.
- 지난 근무일에 기록·휴가 없음 → 미기록(결근). 입사일 이전은 판정 제외.
- 미래·오늘(기록 전)은 판정하지 않음.

## 화면·API

근태는 별도의 **직원 관리 모드**(`/hr`, 라우트 그룹 `(hr)`)로 분리 — `/portal`의
세 번째 카드. 주문 관리 모드와 동일한 헤더형 레이아웃이며 전 직원 접근 가능.

- `/hr/attendance` 내 근태 (전 직원): 출퇴근 체크 · 월별 내 기록 · 휴가 신청.
- `/hr/approvals` 휴가 승인 (manager·admin): 대기 결재 + 최근 처리 내역.
- `/hr/admin` 근태 현황 (admin): KPI 카드(클릭=필터) · 직원별 월 요약 ·
  행 클릭 시 일별 드릴다운·보정 · 휴가 승인 · 대상/정책 관리.
- 주문 관리 모드 헤더에 출퇴근 체크 위젯 유지 (매일 쓰는 체크만 원클릭,
  상세는 직원 관리 모드). 구주소 `/orders/attendance`·`/attendance`는
  새 모드로 리다이렉트.
- API: `/api/attendance/status`(체크), `/api/attendance/records`(월별 조회·관리자 액션),
  `/api/attendance/leaves`(신청·승인). 월별 기록 조회는 `fetchAllRows`로
  PostgREST 1000행 제한 회피.

## 퇴근 체크 확인 · 본인 취소 (2026-10-01 사용자 요청 — 퇴근 버튼 오클릭)

- 퇴근 체크 전 확인창(window.confirm). 출근 체크는 확인 없음(매일 반복, 되돌릴 일 거의 없음).
- 퇴근 체크 후 위젯의 '출근 HH:MM · 퇴근 HH:MM' 옆 **[취소]** — `POST /api/attendance/status { action: 'cancel_check_out' }`.
  당일(work_date = 오늘)만, check_out_at을 비우고 `edited_by = 본인`, `edit_note = '본인 퇴근 취소 (HH:MM 기록 삭제)'`로
  흔적을 남긴다. 출근 시각은 그대로, 다시 퇴근 체크 가능. 지난 날짜·출근 시각 정정은 관리자 보정(근태 현황 adjust)만.

## 작업 유실 기록 (2026-09-30)

공휴일 기능은 2026-08에 한 번 구현해 `claude/employee-attendance-management-a24sn9`
브랜치에 푸시했으나, UI 재조정 세션이 같은 브랜치 이름을 재사용해 force-push하면서
미병합 커밋 3건이 유실됐다(객체 자체가 남지 않아 복구 불가). 200은 이미 main에
병합돼 있어 무사했고, 201 마이그레이션은 사용자가 실행한 상태로 남아 코드만 다시
작성했다. 재구현 시 레거시 role 판정을 `isHrAdmin`으로, 사이드바 직접 수정 대신
`API_OWNERS` 등록으로 맞췄다.

**교훈: 트랙별로 브랜치 이름을 분리한다.** 이 트랙은 이후
`claude/attendance-*` 접두를 사용한다.

### 휴가 취소 정책 (2026-10-12 확정)

- **승인 대기(requested)**: 본인이 취소. 사유 없이 가능.
- **승인됨(approved)**: **인사·총무 수정 권한자만** 취소 (승인권자는 취소 불가 — 결재 번복을
  인사에서 통제한다는 사용자 결정). **취소 사유 필수**(`decide_note`에 저장, 취소자는
  `decided_by`). **지난 날짜도 취소 가능** — 잘못 승인된 건을 바로잡아야 하므로 제한하지 않는다.
- 취소하면 그날은 다시 근무일로 계산된다 — 기록이 없으면 미기록(결근)으로 표시되고
  휴가 일수 집계에서도 빠진다.
- 화면: 휴가 승인(`/hr/approvals`) > 최근 처리 내역의 "승인 취소" 버튼. 권한자에게만 노출
  (`GET /api/attendance/leaves`의 `can_edit`). 내 근태 화면은 승인 대기 건만 취소 버튼이 있다.
- 알려진 한계: 최근 처리 내역은 최근 50건만 보여주므로 아주 오래전에 승인된 건은
  목록에 없을 수 있다(현 인원 규모에서는 수개월치가 들어온다).

### 휴가 일수 = 근무일 기준 (2026-11-04 사용자 지적 → 수정 배포)

- 사용자 지적: 11/06(금)~11/09(월) 연차 신청 내역에 토 · 일이 포함된 것처럼 보인다.
  "주말은 출근일이 아니므로 제외하고 세야 한다."
- 점검 결과: **집계는 이미 맞았다** — `leaveDays`가 주말 · 공휴일을 빼고 세고(위 예는 2일),
  `judgeDay`는 주말을 휴가보다 먼저 판정한다. 문제는 **표시**였다 — 목록 · 승인 화면이 기간만
  보여주고 일수가 없었고, 스케줄 캘린더가 주말 칸에도 휴가를 그렸다.
- 수정:
  - `GET /api/attendance/leaves`가 각 건에 `days`(근무일 기준, 반차 0.5)를 붙이고, 신청 양식
    미리보기용 공휴일 맵(작년 1월 ~ 내년 12월)을 함께 내린다. 표기는 `leavePeriodText` —
    `2026-11-06 ~ 2026-11-09 · 2일`. 적용: 내 근태 휴가 목록 · 휴가 승인(대기 · 처리 내역) ·
    근태 현황 승인 대기.
  - 신청 양식 아래에 "근무일 N일 (달력 M일 중 주말 · 공휴일 제외)" 미리보기.
  - **근무일이 0일인 신청은 서버에서 차단**(주말 · 공휴일만 고른 경우). 승인권자 PC 알림에도 일수 표기.
  - 스케줄: 휴가 이벤트에 `workDaysOnly` — 월 캘린더는 근무일 칸에만, 타임라인 막대는 주말 ·
    공휴일에서 끊어 그린다(`workDaySegments`). 상세 메모에 기간 + 일수. 달을 넘는 휴가는 바깥 공휴일도
    읽어 일수를 센다. 아르바이트 근무기간 등 다른 기간형 일정은 이어서 그린다(변경 없음).
- 저장 방식은 그대로(기간만 저장, 일수는 매번 계산) — 마이그레이션 없음. 공휴일을 나중에 등록해도
  일수가 자동으로 맞춰진다.
- 연차 부여 · 잔여 일수 관리는 아직 없다(미결 후보).
