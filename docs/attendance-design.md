# 근태 관리 설계 (인사·근태 트랙 1단계 — 마이그레이션 200)

## 원칙

- 직원 마스터는 `employees` 단일 테이블. 근태용 새 직원 테이블을 만들지 않고
  `attendance_target`(근태 대상 여부) 컬럼만 추가했다.
- 상태(지각·결근·휴가)는 저장하지 않는다. 정책(`attendance_policy`) ·
  출퇴근 기록(`attendance_records`) · 승인된 휴가(`attendance_leaves`)를 조합해
  화면·집계 시점에 자동 판정한다 (`lib/attendance.ts`의 `judgeDay`).
- 관리자 보정은 기록을 덮어쓰되 `edited_by / edited_at / edit_note`로 감사 이력을 남긴다.
  보정 사유는 필수.
- 모든 테이블 접근은 서버 라우트(service role) 경유. RLS enable + 정책 없음
  (기존 100번대 테이블과 동일 패턴).

## 출퇴근 체크는 등급 구분 없음

sales·manager·admin 모두 동일하게 출퇴근 체크·휴가 신청을 사용한다. 직원 등록 기능
이전부터 쓰던 관리자 계정처럼 `employees`와 연결되지 않은 로그인 계정은
`lib/attendance-employee.server.ts`의 `getAttendanceEmployee`가 최초 사용 시
자동으로 직원 행을 찾아 연결하거나 새로 만든다(이메일 앞부분을 임시 이름으로 사용 —
직원·계정 관리에서 수정). 별도의 연결 절차·화면은 두지 않는다.

체크를 사용하면 `attendance_target`이 자동으로 true가 되어 근태 현황 집계에도 잡힌다.

## 근태 대상 (CLAUDE.md의 미결 질문에 대한 처리)

로그인 계정 없는 직원(거래처 엑셀 적재로 등록된 상담자 21명)의 근태 대상 여부는
코드에서 확정하지 않았다. 마이그레이션 기본값으로 **계정 보유자만 대상**
(`auth_user_id IS NULL → attendance_target = false`)으로 두고, 근태 현황 화면의
"근태 대상 관리"에서 개별로 켜고 끌 수 있다 — 확정은 사용자가 한다.

## 데이터 구조 (200_attendance_base.sql)

| 테이블 | 내용 |
|---|---|
| `employees.attendance_target` | 근태 대상 여부 (기본: 계정 보유자만 true) |
| `attendance_records` | 출퇴근 기록. 직원·날짜(UNIQUE)당 1행. `source` self/admin, 보정 감사 컬럼 |
| `attendance_leaves` | 휴가 신청·승인. requested → approved/rejected/canceled. 반차는 하루짜리만 |
| `attendance_policy` | 단일 행 정책: 출근·퇴근 기준 시각, 지각 유예(분) |
| `attendance_holidays` (201) | 공휴일·휴무일. `source` public(법정)/company(임시공휴일·창립기념일 등) |

공휴일은 근태 현황 화면의 "공휴일 관리"에서 연도별로 관리한다. 201에 2026년 법정공휴일이
적재되어 있다.

**연도별 공휴일 공급 — 공공데이터포털 특일정보 API**

- "OOOO년 공휴일 불러오기" 버튼이 한국천문연구원 특일 정보
  (`SpcdeInfoService/getRestDeInfo`)를 12개월치 호출해 그 해 법정공휴일로 교체한다.
  음력 기반(설날·부처님오신날·추석)·대체공휴일·임시공휴일이 모두 공식 값으로 들어온다.
- 환경변수 `DATA_GO_KR_SERVICE_KEY` 필요 (Vercel 환경변수). 포털이 주는 **일반 인증키
  (Decoding)** 를 넣는다. Encoding 키(%가 포함된 값)를 넣어도 동작하도록 처리돼 있다.
  키가 없으면 버튼 대신 안내가 뜨고 직접 등록만 가능하다.
- 교체 대상은 `source='public'` 행뿐이다. 직접 등록한 회사 휴무(company)는 보존된다.
- API가 0건을 반환하면 교체하지 않는다 — 일시 오류로 기존 공휴일이 지워지는 것을 막는다.
- 해당 연도 공휴일이 0건이면 근태 현황에 경고 배너, 내 근태에 안내 문구가 뜬다.
  등록하지 않으면 그 해 공휴일이 조용히 결근으로 판정되기 때문이다.

연 1회(연말 또는 새해 첫 근태 확인 시) 버튼을 눌러 다음 해를 채우는 것이 운영 루틴이다.

날짜는 KST 기준(`work_date`). timestamptz는 UTC로 저장하고 화면·판정 시 +9h 변환
(한국은 DST 없음).

## 판정 규칙 (lib/attendance.ts)

- 주말(토·일)과 공휴일(`attendance_holidays`)은 근무일에서 제외 — 결근·지각 판정 대상이
  아니고, 휴가 일수 계산에서도 빠진다. 공휴일이 주말과 겹치면 공휴일명을 표시한다.
- 종일 휴가(연차·병가·공가·기타) 승인 → 휴가.
- 출근 체크 있음 → 출근. 기준 시각+유예 초과 체크인 → 지각 (오전 반차 날은 지각 판정 제외).
- 지난 날짜에 출근만 있고 퇴근 없음 → 퇴근 미기록.
- 지난 근무일에 기록·휴가 없음 → 미기록(결근). 입사일 이전은 판정 제외.
- 미래·오늘(기록 전)은 판정하지 않음.

## 권한

| 등급 | 가능 |
|---|---|
| sales | 본인 출퇴근 체크, 본인 기록 조회, 휴가 신청·본인 대기 건 취소 |
| manager | + 전 직원 기록·휴가 조회, 휴가 승인·반려 (본인 신청은 결재 불가) |
| admin | + 기록 보정·삭제, 근태 대상 지정, 정책 수정, 승인된 휴가 취소 |

## 화면·API

근태는 별도의 **직원 관리 모드**(`/hr`, 라우트 그룹 `(hr)`)로 분리 — `/portal`의
세 번째 카드. 주문 관리 모드와 동일한 헤더형 레이아웃이며 전 직원 접근 가능.

- `/hr/attendance` 내 근태 (전 직원): 출퇴근 체크 · 월별 내 기록 · 휴가 신청.
- `/hr/approvals` 휴가 승인 (manager·admin): 대기 결재 + 최근 처리 내역.
- `/hr/admin` 근태 현황 (admin): KPI 카드(클릭=필터) · 직원별 월 요약 ·
  행 클릭 시 일별 드릴다운·보정 · 휴가 승인 · 대상/정책 관리.
- 주문 관리 모드 헤더에 출퇴근 체크 위젯 유지 (매일 쓰는 체크만 원클릭,
  상세는 직원 관리 모드). 구주소 `/orders/attendance`·`/attendance`는
  새 모드로 리다이렉트.
- API: `/api/attendance/status`(체크), `/api/attendance/records`(월별 조회·관리자 액션),
  `/api/attendance/leaves`(신청·승인). 월별 기록 조회는 `fetchAllRows`로
  PostgREST 1000행 제한 회피.
