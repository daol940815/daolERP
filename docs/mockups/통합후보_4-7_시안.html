화면 통합 후보 4~7 시안 (2026-09-30) — 1~3(기초잔액 / 자금 · 계좌 / 카드 내역)은 탭 통합으로 구현·배포했습니다. 4~7은 작업 흐름이 바뀌므로 확정 전 시안입니다. 각 절의 왼쪽 사이드바는 통합 후 메뉴이며, 삭제 표시는 사라지는 항목, 신규 표시는 새 항목입니다. 숫자는 예시(가공)이며 실제 데이터가 아닙니다. 옛 주소는 모두 새 화면의 해당 탭으로 리다이렉트됩니다(1~3과 같은 방식). 파란 상자는 확정이 필요한 질문입니다.

5통장 내역 + 통장 거래 분류 → 통장 내역 화면 안의 '분류 작업' 탭

통장 거래 분류(/bank-classify)는 통장 내역의 미분류 건을 묶어서 확정하는 작업 화면인데 메뉴가 떨어져 있어 왕복이 잦습니다. 통합안은 통장 내역에 [거래 내역 | 분류 작업] 탭을 두고, 사이드바의 계좌별 바로가기(계좌 선택)를 두 탭이 공유합니다. 분류 작업 탭에서 묶음을 확정하면 거래 내역 탭에 바로 반영되고, 탭 이름 옆에 미분류 건수가 붙습니다.

통합 전

  • 통장 내역 (계좌별 바로가기 하위)
  • 통장 거래 분류 (별도 항목, 계좌 필터 없음)

통합 후

  • 통장 내역 = [거래 내역] 탭 (현재 화면 그대로) + [분류 작업] 탭 (현재 분류 화면 + 계좌 필터)
  • 통장 거래 분류 항목 삭제 (옛 주소는 분류 작업 탭으로 이동)
  • 계좌별 바로가기는 선택한 탭을 유지한 채 계좌만 바꿈

7매입처 관리 + 매입 결제 예외(매입 사이클) → 매입처 관리 안 '결제 예외' 탭

매입 사이클 예외(/purchase-cycle)는 "ERP 발주 → 계산서 → 지급" 흐름에서 거래처 × 월 단위로 확인이 필요한 건을 뽑는 화면이고, 거래처명을 누르면 매입처 관리 상세로 갑니다. 통합안은 매입처 관리에 [매입처 목록 | 결제 예외] 탭을 두고, 목록 탭의 각 매입처 행에 예외 건수 배지를 붙여 상세로 가지 않아도 문제를 보게 합니다. 매입처 관리는 영업·주문 / 회계·재무 / 경영 현황 세 영역에서 같은 화면을 쓰므로 세 곳 모두 탭이 보이되, 결제 예외 탭은 수금·정산 조회 권한이 있어야 열립니다.

통합 전

  • 영업·주문 › 거래처 관리 › 매입처 관리 / 수금·정산 작업 › 매입 결제 예외
  • 회계·재무 › 매입처 관리 / 경영 현황 › 매입처 관리 (예외 화면은 영업·주문에만)

통합 후

  • 매입처 관리 = [매입처 목록] 탭 (행마다 예외 배지) + [결제 예외] 탭 (현재 예외 화면)
  • 수금·정산 작업 › 매입 결제 예외 항목 삭제 (옛 주소는 결제 예외 탭으로)
  • 세 영역 모두 같은 탭 구조, 결제 예외 탭은 수금·정산 조회 권한자에게만
