데이터 원천 — 지금 되는 것과 추가가 필요한 것

항목원천현재필요한 작업
① 직원 휴가 attendance_leaves (200) — 승인 건 있음 없음. 바로 쓸 수 있다. 승인 대기 건을 흐리게 함께 보일지만 결정.
② 영업일정 contact_activities (105) — 지금은 activity_date(실행한 날)와 next_action(다음 할 일, 텍스트)뿐 예정일 없음 planned_date 컬럼 추가 + 영업일지 화면에 "예정일" 입력칸. 영업일지 트랙(700)·개인화면 트랙(300)과 조율 필요.
③ 업무일정 erp_work_logs (700) — 지나간 업무 기록(work_date·action·content). 예정 개념이 없다 기록만 아래 결정 1 참고 — 지난 기록을 보여줄지, 예정 입력을 새로 만들지.
④ 아르바이트 근무기간 employees.work_start / work_end (109) + employment_type='parttime' 있음 없음. 인사 트랙의 parttime_terms가 생기면 시즌별로 더 정확해진다.
⑤ 직원 생일 employees — 생일 컬럼 없음(hire_date만 있음) 컬럼 없음 birth_date 추가(200번대 마이그레이션) + 직원 상세에 입력칸. 결정 2(노출 범위) 필요.
공휴일(배경) attendance_holidays (201) 있음 없음.
저장은 늘리지 않는다 — 스케줄 화면 전용 테이블은 만들지 않고, 각 원천을 월 단위로 읽어 합쳐서 보여준다. 새로 저장하는 것은 생일(직원 마스터 컬럼)과 영업 예정일(영업일지 컬럼)뿐이고, 둘 다 원래 그 데이터가 있어야 할 자리다.

확정해주실 것

  1. 업무일정을 "예정"으로 만들까요, "기록"으로 볼까요?
    현재 업무일지(erp_work_logs)는 상담·주문 등에서 자동으로 쌓이는 지나간 기록입니다. (a) 기록 보기 — 입력 부담 0, 대신 "다음 주에 누가 뭐 하는지"는 안 보입니다. (b) 예정 입력 신설 — 미래 일정이 보이지만 매번 직접 입력해야 하고, 아무도 안 쓰면 빈 칸이 됩니다. (c) 섞기 — 지난 날짜는 기록, 앞으로는 예정 입력(권장).
  2. 생일을 누구까지 보나요?
    (a) 인사·총무와 사장님만 (b) 전 직원 공개 (c) 월·일만 공개하고 연도는 인사만. 생일은 개인정보라 수집 동의가 필요할 수 있고, 입력을 선택으로 둘지도 정해야 합니다.
  3. 휴가 사유를 캘린더에 보일까요?
    병가·경조사는 민감합니다. 기본은 "휴가"로만 표시하고 사유는 숨기는 쪽을 권합니다. 승인 대기 건을 흐리게 함께 보일지도 함께 정해주세요(겹치기 확인에 유용).
  4. 일반 직원도 이 화면을 보나요?
    (a) 인사·총무 + 사장님만 (b) 전 직원이 팀 일정을 조회 (c) 전 직원이 보되 본인 외에는 이름·휴가 여부만. 현재 메뉴 권한 구조상 hr 그룹에 넣으면 (a)가 됩니다.
  5. 어느 세션에서 만들까요?
    스케줄은 인사·총무 트랙(docs/hr-track.md) 진행 순서 4번이고 담당은 별도 세션입니다. 이 세션(근태)에서 먼저 만들면 트랙 문서에 기록해 충돌을 막겠습니다.
단계를 나눌 수 있습니다. ①휴가 · ④아르바이트 · 공휴일은 지금 데이터만으로 바로 됩니다(1단계). ⑤생일은 컬럼 하나 추가면 되니 같이 넣을 수 있습니다. ②영업일정과 ③업무일정은 다른 트랙의 입력 화면이 함께 바뀌어야 해서 2단계로 두는 편이 안전합니다.
