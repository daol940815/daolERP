완료 회신 시안 — 처리한 사람이 요청한 사람에게 결과를 알린다

사용자 결정(2026-11-05): 회신해야 완료 · 회신 대상 = 주문 진행 요청 건 + 요청 없이도 상담자와 입력자가 다른 주문 · 1차는 담당 → 요청자 한 방향 · 처리 불가 회신이면 요청은 요청자에게 되돌아감.
회신은 주문 상세(전환 전 처리 불가는 상담 상세)에서 남기고, 받는 사람에게 사이드바 알림 + PC 알림이 갑니다.

전체 흐름 — 두 가지 경우

가. 주문 진행 요청 건 상담일지에서 요청 → 다른 직원이 처리
1. 요청옥광일이 상담일지 작성 → 주문 진행 담당 김승현
→
2. 주문 입력됨김승현이 주문으로 전환 → 요청 상태 회신 대기 (완료 아님)
→
3. 발주 · 확인김승현이 발주서 발송 · 배송일 확인
→
4. 완료 회신주문 상세에서 "완료 회신" → 옥광일에게 알림 → 완료
전환 전에 처리할 수 없으면 상담 상세에서 처리 불가 회신(사유 필수) → 요청이 옥광일에게 되돌아가고, 다른 직원에게 다시 요청하거나 직접 진행합니다.
나. 요청 없이 상담자 ≠ 입력자인 주문 예: 김재형 대표 담당 고객의 전화를 영업지원팀이 받아 바로 입력
1. 주문 입력김주연이 주문 입력 · 상담자 = 고객 다올 담당 김재형 (자동)
→
2. 회신 대기상담자 ≠ 입력자 → 자동으로 회신 대기
→
3. 완료 회신김주연이 처리 후 회신 → 김재형에게 알림 → 완료

경우회신하는 사람받는 사람설명

F. 확인 부탁드릴 것

시안 확정 전에 정해주세요

  1. 적용 시작일 — 가안: 배포일 이후 입력된 주문부터. 지난 주문은 회신 대상 아님.
    이유: 상담자 = 고객 다올 담당으로 바뀐 뒤(112) 영업지원팀이 입력한 주문은 대부분 상담자 ≠ 입력자라서, 10월 이후 주문이 한꺼번에 "회신 대기"로 쌓입니다.
  2. 회신 건수가 많아지는 점 — 나. 경우가 들어가면 영업지원팀이 입력하는 주문 대부분이 회신 대상이 됩니다(하루 입력 건수만큼). 가안: 그대로 진행.
    부담이 크면 대안: 나. 경우는 회신 없이 "주문 입력됨" 자동 알림만 보내고 완료로 봄.
  3. 로그인 계정이 없는 상담자 — 엑셀 적재로 생긴 계정 없는 직원이 상담자면 알림을 받을 수 없음. 가안: 받는 사람이 계정 없는 직원뿐이면 회신 대상에서 제외.
  4. 회신할 수 있는 사람 — 가안: 입력자 + 관리자급(대신 회신). 아르바이트가 입력한 주문은 아르바이트가 회신.
  5. 처리 불가 회신과 주문 취소 — 가안: 회신은 주문을 자동 취소하지 않음(원본 보존 · 확정은 사용자). 취소는 기존 주문 취소로 따로.
  6. 취소 · 재발행 — 가안: 취소된 주문은 회신 대상에서 빠짐. 재발행 시 회신 이력은 새 주문으로 옮김(결제 연결과 같은 방식).
