### 원가표 실물 반영 (2026-08-08, 사용자 확정 — 마이그레이션 503)

원가표 엑셀(2,358행) 분석·전수 검증으로 확정된 구조:

- **품번 체계 확정**: `연도-페이지-상품(-옵션)` (예: 25-25-14-01). 전 행 기재, 중복 0.
- **가격 관계 (전수 검증, 예외 0)**: 개별매입가 = 지점매입가 + 카톤외택배비 /
  개별판매가 = 지점판매가 + 카톤외택배비. 개별매입가는 기존 ERP가 배송비를
  별도 표기 못해 만든 파생 개념 — **저장하지 않고 주문 입력 시 자동 계산**.
- **지점 배송비 공식 (확정)**: 꽉 찬 카톤 수 × 카톤택배비 + (나머지 낱개 있으면
  카톤외택배비 1건). 이전의 올림 방식은 과다 책정이라 폐기.
- erp_products 추가: loose_shipping_fee(카톤외택배비) · category(목차) ·
  option_name(옵션명).
- **업로드 파서 v2**: 회사 원가표를 그대로 업로드 가능 — '원가표' 시트만 읽고
  ('116 시계조명' 등 작업 시트 무시), 2행 헤더(택배비→카톤단위/카톤외) 처리,
  `*` 접두·줄바꿈 흡수. 카탈로그 제작용 컬럼(카탈로그 표기용 상품명·소비자가·
  구성·재고·카탈로그)은 무시(사용자 확인). 메모 자리채움값('1'/'0') 제외.
  개별판매가=지점판매가+카톤외 관계 어긋난 행 수를 결과에 보고(relation_mismatch).
- 매입처 123곳의 담당자·연락처·이메일이 원가표에 있음 — **3단계 발주서 메일
  발송의 원천**으로 사용 예정 (현재는 미적재).

### 부가상품 옵션 (2026-08-08, 사용자 확정 B안 — 마이그레이션 504)

3. [반영] 품목별 기타사항: erp_consultation_items.option_note. 상담 단위 기존
   컬럼은 보존(읽기 전용 표시). 주문 전환 시 상태·기타는 품목 메모로 병합
4. [반영] 드롭다운 확대: 입력칸보다 넓게(w-max, max-w 34rem)·행 여유·품명 줄바꿈
5. [반영] 마진율(%): 품목 행·하단 합계 모두 표기
6. [반영] 매입배송비 선택: 없음/카톤단위/카톤외 셀렉트 (금액 자동)
7. [2차] 수정된 발주서 파일 첨부 — 저장소(Storage) 설계 후
8. [대기] 발주서 양식 개정 — 영업지원팀 새 양식 실물 수령 후

**기능 추가 요청**
9. [반영] 요아럽 판매가 발주: vendors.po_use_sale_price (509에서 요아럽 지정).
   발주서 생성 시 단가=판매가·배송비=판매 배송비·합계=판매합계(할인 반영)로
   스냅샷. 발주 화면에 '판매가 발주' 배지, 미발주 목록 금액도 판매가 기준 표시
10. [반영] 자체 양식 표기: 발주 섹션 그룹·발주서 카드·발주서 이력에 '자체 양식'
    배지. 매입처 관리(erp-aliases) 편집에 자체 양식·판매가 기재 체크박스 추가
11. [반영 추정] 발주서 내용 미리보기(실제 양식 재현) — 실무자 확인 대기
12. [반영] 할인 별도 표기란: 상담품목 할인 컬럼(적용 시 붉은 강조)+합계에 할인 합계
13. [반영] 카톤단위 자동 표기: 상담품목 카톤 컬럼 (원가표 자동)
14. [반영] 결제·발송 정보 확장: 계산서 이메일·팩스·사업자등록번호·대표자명 (509)
15. [대기] 거래명세서 자동출력 — 명세서 양식 실물 필요
16. [2차] 주문 취소·재등록(홈택스 방식) — 현행 수정요청 승인과의 관계 설계 후
- 품절 관리(사용자 확정): 품목 관리 화면 품절/품절해제 버튼 + 품절 배지,
  상담·주문 입력 품번 검색 드롭다운에 품절 표시, 품절 상품 선택 시 상태 자동 '품절'.
  엑셀 다운로드에 품절 컬럼(참고용) 추가.

## 배경 — 왜 만드는가 (기존 ERP의 4대 한계)

1. 주문처 수기 입력 → 오타 → 별칭 지옥 (회계 매칭 문제의 뿌리)
2. 배송 미연동 (delivery_status 전부 NULL)
3. 익일 수정 불가 → 음수 상계 주문으로 정정 (데이터 오염)
4. 검색·조회 불편

## 확정된 설계 결정

- **병행 운용**: `erp_orders.source = 'upload'(기존 ERP 엑셀) | 'direct'(자체 입력)`.
  하류(허브·수금 매칭·회계)는 수정 없이 두 소스를 함께 소비. 시범 직원 1~2명 →
  확산 → 기존 ERP 업로드 중단 순으로 전환.
- **단계**: 1단계 완료 — 주문 포털 셸(/orders, 사이드바형), 주문 현황 목록(내 주문),
  직원·계정 관리(ID 로그인, 등급 3단계), 모드 선택. / **2단계(다음)** — 품목 마스터 +
  주문 입력 + 주문·품목 엑셀 업로드 + 수정 승인 워크플로. / 3단계 — 발주서 엑셀 생성 +
  네이버 SMTP 발송(백업 CC) + 배송 관리 통합.
- **수정 정책**: 당일 자유 수정, 익일 이후는 수정 요청 → 중간 관리자(manager) 승인.
  음수 상계 주문 방식 폐지.
- **주문 입력 필수 항목**: 거래처 담당자(contacts 마스터) + 상담자(employees 마스터).
  다올직원(입력자)은 로그인 계정 자동 기록. 주문처는 vendors 마스터 선택(자유 입력 금지).
  상담자 비인명 값은 공란 정책(직원 마스터 화이트리스트 대조).
- **발주서(3단계)**: 품목의 매입처(purchase_vendor_name)별 자동 분리, 기존 엑셀 양식
  재현, 네이버 SMTP 발송. SMTP 발송분은 보낸메일함에 안 남으므로 백업 CC + 시스템
  발송 이력으로 보완.
- **미수 규칙**: direct 주문은 입금 매칭 전액 차감 (마이그레이션 107 컷오프 규칙은
  upload 주문에만 적용 — lib/vendor-hub.ts cutoffAlloc 참조).
- **UI 방향**: "입력은 기존을 닮게, 조회는 새롭게". 시안 3종이 docs/mockups/에 있음 —
  주문목록(신규 톤) / 주문입력(신규 톤) / 주문입력(클래식 기존 ERP풍).
  신규 vs 클래식 톤은 실무자 의견으로 결정(구현 비용 동일). 실무자 의견 수렴 중.
- **개인화면 트랙(300번대)과 연계**: 직원 워크스페이스(B안) 사이드바의 주문 메뉴가
  단계적으로 열리는 구조. `app/(orders)/` 영역은 개인화면 트랙과 공유 —
  main 병합 전 rebase 필수.

## 대기 중인 사용자 입력 (진행 전 확인)

1. 실무자 의견 (UI 톤·목록 화면 사용성) — 수렴 중
2. 기존 화면 해석 미답 3건: 상태 점 2개의 의미 / 검사상태 정의 / 품번(상품 마스터) 체계
3. 기존 ERP 주문상세·주문추가 화면 캡처 (입력 화면 배치를 실물에 맞추기 위함)
4. 품목 마스터용 상품 엑셀 (품번·품명·매입처·판매가·매입가) — UI 확정과 무관하게 선행 가능
5. 발주서 엑셀 양식 / 배송현황 HTML 구현물 / 네이버 SMTP 계정 / 시범 운용 직원 지정
