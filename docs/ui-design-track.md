## 배경 (사용자 요청 2026-11-25)

1. 입력 표를 **엑셀 파일처럼 셀 형태**로 — 직사각형보다 **약간 둥근 칸**.
2. **항목별 구분이 뚜렷하게** — 지금은 비슷한 색이라 **눈이 피로하다는 의견이 다수**.
3. 시안을 본 뒤: "현재 색감은 흐릿하다" → 여러 색감 비교 요청 → "이 디자인톤을 신규 ERP 전체에 반영 가능한가?" → 별도 UI 세션 개설.

참고 이미지(사용자 제공, 대화에만 있음): ① 다른 시스템의 "상담 내역" 표 — 위에 매출합계 · 매입합계 · 이익금 · 마진 요약,
품절 상태 칸 빨간 칠 ② 스프레드시트 앱 — 칸마다 둥근 테두리 · 칸 사이 간격, 누른 칸은 진한 테두리, 숫자 오른쪽 정렬, 아래 시트 탭.

## 결정 대기 (사용자)

1. **색감 선택**: A~E 중 하나 또는 조합(예: A의 머리줄 + E의 입력 칸).
2. **전체 색 조정 방식**: 기본 테마를 바로 바꿀지 / 테마 하나로 며칠 시험 후 기본값 변경(권장 — 전 직원 화면이 한꺼번에 바뀜).
   주의: 직원별 화면 설정은 "글자 크기 3단계 · 색 테마 4종만"이 사용자 결정(113, CLAUDE.md UI 관례) — 5번째 테마 추가는 이 결정을 바꾸는 일이라 확인 필요.
3. **주문서(신규 주문 · 주문 상세) 주문 상품 표도 함께** 바꿀지(권장 — 같은 규칙의 표).

## 조사 결과 · 권장 진행 순서 (2026-11-25)

- **색(선명도 · 대비)은 전체 한 번에 가능**: 기본 회색은 Tailwind `slate` = 테마 변수(`app/globals.css` `--slate-50`~`950`, 테마 default · navy · green · warm,
  `tailwind.config.ts`, `lib/ui-prefs.ts` `UI_THEME_SWATCH`와 맞출 것). slate 단계를 진하게 하면 전 화면 테두리 · 머리줄 · 보조 글자가 함께 또렷해짐.
  의미 색(blue · amber · red · green …)은 테마 대상 아님 — 화면별 클래스.
- **칸 모양(엑셀형 셀 · 묶음 색)은 화면별 이전 필요**: 표가 있는 화면 89개 · 입력 칸 화면 105개(2026-11-25 grep), **공용 표 · 입력 부품이 없음**
  (`components/ui`에는 PeriodPresets · PageTabs · SearchableSelect 등만). 전역 CSS로 input을 덮어쓰는 방식은 배치가 깨질 위험이 커서 비권장.
- 권장 순서: ① 색감 결정 → ② 공용 부품(셀 입력 칸 · 묶음 머리줄 · 계산 칸 · 요약 알약 — `components/ui/` 신설 권장) → ③ 상담 품목 표
  (`app/(orders)/orders/consultations/consult-form.tsx` 품목 표 ~1270행~, colgroup 너비 · 최소 폭 1774px 주석 참고) → ④ 주문서 주문 상품 표
  (`app/(orders)/orders/order-form.tsx`) · 발주서 품목 → ⑤ 결제 기록 등 다른 입력 표 → ⑥ 조회 목록 표는 머리줄 대비 · 줄 구분만(대부분 색 조정으로 해결).
- 확정되면 **CLAUDE.md UI 관례에 전체 규칙으로 기록**(다른 트랙 세션의 새 화면도 같은 모양으로 만들도록).

## 범위 변경 · 현황 조사 (2026-11-25 저녁, UI 세션)

- **사용자 결정**: 상담일지 한정이 아니라 **신규 ERP 전체 UI 디자인을 통일**한다. 먼저 현재 UI 전수 확인 → 보고 → 통일 기준 결정 순.
  위 "결정 대기" 3건(색감 · 적용 방식 · 주문서)은 사용자 "선호 없음" 응답 — 전체 통일 기준을 정할 때 함께 다시 정한다.
- **조사 방법**: 코드 전수 집계(화면 92개 · tsx 202개). 실제 화면 캡처는 못 함(DB 키 없음).
- **핵심 발견**
  1. **테마 변수는 slate만, 실제 화면은 gray가 주력** — 색 클래스 gray 5,601 : slate 1,598. gray는 테마 대상이 아니라서
     "slate 단계를 진하게 하면 전 화면이 또렷해진다"는 위 조사 결과는 **틀림**(테두리 border-gray-200/300 1,315곳, 머리줄 · 보조 글자 대부분 gray).
     전체 색 조정을 하려면 gray도 변수로 묶거나 gray → slate 일괄 치환이 먼저.
  2. **흐릿함의 원인**: 보조 글자 text-gray-400 1,307곳(흰 바탕 대비 약 2.5:1, 권장 4.5:1 미달) — 표 머리줄 142개 중 60여 개가 이 색.
     줄 구분 border-gray-50/100 약 270곳(거의 안 보임). 글자 11px 655곳 · 10px 233곳.
  3. **공용 부품 없음**: input 577개에 클래스 조합 237가지, button 973개에 677가지. 파일마다 `inp` · `inputCls` · `btn` · `card` · `th` 상수를 따로 정의(약 40곳).
  4. **화면 사이 불일치**: 표 머리줄 2계열(흰 바탕 + gray-400 글자 약 60 / gray-50 바탕 + gray-500 글자 약 45) + slate 계열 약 10,
     입력 칸 모서리 rounded-lg 234 : rounded 120, 높이 py-1.5 169 : py-1 122 : py-2 44, 제목 text-2xl 43 : text-xl 23,
     모달 배경 진하기 30 · 40 · 50 · 60% 혼재, 그림자 6단계 혼용.
  5. **이미 통일된 것**: 카드(bg-white border-gray-200 rounded-xl, 약 150곳), 주 버튼(bg-slate-900, 211곳), 포커스(ring-2 slate-900),
     표 칸 여백(px-3 py-2 주력), 의미 색(빨강 = 위험 · 미수, 주황 = 주의, 파랑 = 정보 · 링크, 초록 = 완료), 숫자 오른쪽 정렬 + tabular-nums.
  6. 재고 관리 · 자금 · 통장 내역 등 최근 화면은 slate, 오래된 회계 화면은 gray — 만든 시기에 따라 갈림.

### 실제 화면 확인 (2026-11-25, 사용자 제공 키 · 시험 계정 test001)

- 로컬 실행 후 메뉴 화면 54개 캡처(1600x950, 기본 테마 · 글자 보통). 캡처는 세션 임시 폴더에만 두고 저장소에 올리지 않음. 상세 · 모달 · "크게" · 다른 테마는 미확인.
- 화면에서 확인된 불일치(코드 집계에 더해):
  1. **상단 띠**: 회계 · 재무 / 경영 현황 화면에는 본문 위에 흰 띠(작은 제목 + 날짜)가 있고 영업 · 주문 / 인사 · 총무 / 내 업무에는 없음. 띠 제목과 본문 제목이 중복(거래 내역 / 통장 내역, 분개 현황 / 분개장).
  2. **본문 폭**: 전체 폭 화면과 가운데 좁은 폭 화면이 섞임 — 같은 성격인데도 다름(거래처별 매출 분석 좁음 / 거래처 정산 대조 넓음, 대시보드 · 자금 계좌 · 분개장 · 계정과목 · 기초잔액 좁음).
  3. **제목 줄**: 설명이 제목 옆(품목 관리 · 발주서 · 업무일지) / 제목 아래(대부분) / 없음. 주 버튼이 오른쪽 위(대부분) / 제목 옆(영업일지) / 표 바로 위(직원 등록 · 매입처 등록).
  4. **블록 순서**: KPI → 기간 → 칩(주문내역 · 계산서) / 기간 → KPI(매출처 · 매입처 · 원장) / 필터 → KPI(미수금 · 미지급금).
  5. **표**: 통장 내역만 격자형(세로선 · 줄 색 · 자체 페이지 넘김), 예상 부가세만 진한 남색 머리줄, 나머지는 머리줄이 거의 안 보일 만큼 옅음. 줄 높이도 주문내역 · 발주서(한 줄에 2~3단)와 원장류(한 단)가 크게 다름.
  6. **입력 화면**(상담 기록 · 신규 주문): 입력 칸 테두리가 노랑 · 분홍 · 회색으로 섞여 있고 모두 옅어 칸 경계가 약함.
  7. **행 안 버튼**: 검정 채움(연결 · 수금) / 회색 테두리(수정 · 내용) / 빨강 테두리(삭제) 혼재, 크기 제각각.
  8. 통일돼 보이는 것: 진한 사이드바, 흰 카드, 기간 프리셋 줄, 선택 칩(진한 알약), 탭 줄, 빈 상태 문구, 금액 색(미수 빨강 · 입금 파랑).
