# UI 디자인 트랙 — 인수인계 문서

개설 2026-11-25 (사용자 결정: "UI를 관리하는 별도 세션을 만들어서 진행"). 마이그레이션 없음(화면 · 스타일만).
상담 · 영업 · 업무일지 트랙(docs/consultation-journal-track.md)에서 분리. 메뉴 · 권한 구조는 별개 트랙(docs/ui-reorg-track.md).

## 배경 (사용자 요청 2026-11-25)

1. 입력 표를 **엑셀 파일처럼 셀 형태**로 — 직사각형보다 **약간 둥근 칸**.
2. **항목별 구분이 뚜렷하게** — 지금은 비슷한 색이라 **눈이 피로하다는 의견이 다수**.
3. 시안을 본 뒤: "현재 색감은 흐릿하다" → 여러 색감 비교 요청 → "이 디자인톤을 신규 ERP 전체에 반영 가능한가?" → 별도 UI 세션 개설.

참고 이미지(사용자 제공, 대화에만 있음): ① 다른 시스템의 "상담 내역" 표 — 위에 매출합계 · 매입합계 · 이익금 · 마진 요약,
품절 상태 칸 빨간 칠 ② 스프레드시트 앱 — 칸마다 둥근 테두리 · 칸 사이 간격, 누른 칸은 진한 테두리, 숫자 오른쪽 정렬, 아래 시트 탭.

## 지금까지 만든 시안

- `docs/mockups/상담품목_셀UI_시안.html` — 상담 품목 표 셀 UI(누르면 고쳐지고 합계 · 마진 재계산).
  칸 = 입력 상자 하나 · 칸 간격 4px · 모서리 7px · 글자 13px · 숫자 오른쪽 정렬 · 누른 칸 진한 테두리.
  묶음 띠(품목 · 판매 · 매입 · 결과) + 묶음 색(품목 회색 · 판매 파랑 · 매입 주황 · 결과 초록 — 파랑/주황은 색약에도 갈림).

## 결정 대기 (사용자)

1. **색감 선택**: A~E 중 하나 또는 조합(예: A의 머리줄 + E의 입력 칸).
2. **전체 색 조정 방식**: 기본 테마를 바로 바꿀지 / 테마 하나로 며칠 시험 후 기본값 변경(권장 — 전 직원 화면이 한꺼번에 바뀜).
   주의: 직원별 화면 설정은 "글자 크기 3단계 · 색 테마 4종만"이 사용자 결정(113, CLAUDE.md UI 관례) — 5번째 테마 추가는 이 결정을 바꾸는 일이라 확인 필요.
3. **주문서(신규 주문 · 주문 상세) 주문 상품 표도 함께** 바꿀지(권장 — 같은 규칙의 표).

## 조사 결과 · 권장 진행 순서 (2026-11-25)

- **색(선명도 · 대비)은 전체 한 번에 가능**: 기본 회색은 Tailwind `slate` = 테마 변수(`app/globals.css` `--slate-50`~`950`, 테마 default · navy · green · warm,
  `tailwind.config.ts`, `lib/ui-prefs.ts` `UI_THEME_SWATCH`와 맞출 것). slate 단계를 진하게 하면 전 화면 테두리 · 머리줄 · 보조 글자가 함께 또렷해짐.
  의미 색(blue · amber · red · green …)은 테마 대상 아님 — 화면별 클래스.
- **칸 모양(엑셀형 셀 · 묶음 색)은 화면별 이전 필요**: 표가 있는 화면 89개 · 입력 칸 화면 105개(2026-11-25 grep), **공용 표 · 입력 부품이 없음**
  (`components/ui`에는 PeriodPresets · PageTabs · SearchableSelect 등만). 전역 CSS로 input을 덮어쓰는 방식은 배치가 깨질 위험이 커서 비권장.
- 권장 순서: ① 색감 결정 → ② 공용 부품(셀 입력 칸 · 묶음 머리줄 · 계산 칸 · 요약 알약 — `components/ui/` 신설 권장) → ③ 상담 품목 표
  (`app/(orders)/orders/consultations/consult-form.tsx` 품목 표 ~1270행~, colgroup 너비 · 최소 폭 1774px 주석 참고) → ④ 주문서 주문 상품 표
  (`app/(orders)/orders/order-form.tsx`) · 발주서 품목 → ⑤ 결제 기록 등 다른 입력 표 → ⑥ 조회 목록 표는 머리줄 대비 · 줄 구분만(대부분 색 조정으로 해결).
- 확정되면 **CLAUDE.md UI 관례에 전체 규칙으로 기록**(다른 트랙 세션의 새 화면도 같은 모양으로 만들도록).

## 지켜야 할 기존 규칙 (CLAUDE.md UI 관례)

- `npm run build` 앞단 `check-ui`(scripts/check-ui.mjs): 고정 px 글자(`text-[11px]` → `text-[0.6875rem]`) · 클래스 안 색 코드(`bg-[#…]`) 금지 — 시안의 hex는
  Tailwind 색 이름 또는 CSS 변수로 옮길 것. 기본 회색은 slate · gray만.
- 글자 크기 설정 "크게"에서 한 번 확인(고정 폭 칸 줄바꿈). OS 다크 모드 자동 전환은 제거됨.
- 화면을 고치면 `lib/help-registry.ts` 해당 화면 `updated` + `changes` 한 줄(check-help).
- 화면 신설 · 개편은 시안(HTML) → 사용자 확인 → 구현.
- 상담 · 주문 표의 동작(품번 검색 콤보, 옵션 추가, 배송명단 카드, 쌍방향 고객 추천 등)은 상담 트랙 · 주문 트랙 소관 — 모양만 바꾸고 동작은 건드리지 말 것.
